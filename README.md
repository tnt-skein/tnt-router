# tnt-router

Маршрутизация HTTP-запросов для Tarantool: маршруты деревом участков
пути, параметры с ограничениями, группы со слоями, адреса по имени
и подписанные ссылки, раздача файлов и ответ по кускам. Запрос и ответ —
обычные таблицы, поэтому роутер проверяется без сервера, а поверх
`http.server` ставится одним вызовом.

```lua
local router = require('tnt.router')

router.get('/customers/:id<int>', function(request)
    return router.json({ id = request.params.id, page = request.query.page })
end, { name = 'customer.show' })

router.url('customer.show', { id = 7 })   --> /customers/7

local httpd = require('http.server').new('0.0.0.0', 8080, { log_requests = false, idle_timeout = 60 })

router.attach(httpd, { max_body = 1024 * 1024, body_timeout = 60 })
```

Зависимости: рок `http` (сервер, на который роутер ставится, и таблица
типов содержимого), `tnt-must` (проверка аргументов с виной
на вызывающем), `tnt-hash` (HMAC подписанных ссылок и сверка
за постоянное время), `tnt-clock` (срок чтения тела и длительность
ответа), `tnt-context` (контекст запроса на теле потока), `tnt-date`
(даты HTTP у раздачи), `tnt-id` (азбука опознавателя происшествия),
`tnt-log` (журнал отказов), `tnt-fs` (присланные файлы пишутся
и большие файлы раздачи читаются кусками, отказ диска — пара с родом),
`tnt-external` (подмена часов, случайности и соседей в проверках)
и `tnt-metrics` (ряды запросов и длительности). Соседей `tnt-validate` и `tnt-middleware`
роутер берёт по имени, если они стоят.

## Зачем

Приложение начинается с того, что запрос надо отдать нужному
обработчику, и на этом месте набегает всё, что потом трудно чинить.
Пакет делает шесть вещей:

- **Маршруты — деревом участков пути**, а не перебором образцов:
  постоянный участок важнее параметра, параметр с ограничением —
  параметра без него, а несовпавшее ограничение даёт 404, а не 500
  из глубины обработчика.
- **Граница тела держится до маршрута**: предел и срок чтения, форма
  и присланные файлы разбираются потоком, большой файл уходит
  во временный, а не в память узла.
- **Отказы — одним договором**: 404, 405 с `Allow`, 500 с опознавателем
  происшествия и отказы тела роутер отвечает сам, в JSON, а свой
  обработчик отказов подставляется одним вызовом.
- **Адреса по имени**: путь, полный адрес от адреса приложения,
  подписанная ссылка со сроком и слой её сверки, канонический адрес
  страницы; схема и узел — из настройки, а не из присланных заголовков.
- **Ответ по кускам и смена протокола**: поток держит в памяти один
  кусок и рвётся без завершающего куска при отказе источника; ответ 101
  отдаёт соединение обработчику.
- **Раздача файлов** из каталога или из памяти процесса: тип
  по расширению, метка версии и 304, срок жизни копии, большие файлы
  кусками, запасная страница одностраничного приложения; шаг вверх,
  скрытые файлы и ссылки наружу не уходят.

Каждый ответ ложится в ряды метрик: запросы по способу, шаблону
маршрута и коду и длительность ответа.

## Установка

```sh
tt rocks install tnt-router --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-router.git
cd tnt-router && tt rocks make --server=https://tnt-skein.github.io/rocks
```

Необязательные соседи — ставятся отдельно, если нужны:

```sh
tt rocks install tnt-validate --server=https://tnt-skein.github.io/rocks    # ограничения параметров правилами
tt rocks install tnt-middleware --server=https://tnt-skein.github.io/rocks  # слои, названные именем
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `get`, `head`, `post`, `put`, `patch`, `delete`, `options`, `any` | объявить маршрут: шаблон, обработчик, `{ name, middleware }` |
| `group(prefix, opts, fn)` | маршруты с общим началом пути и общими слоями |
| `serve(prefix, root, opts)` | раздача каталога; `files(opts)` — обработчик раздачи сам по себе |
| `dispatch(request)` | ответ на запрос-таблицу, без сервера |
| `attach(httpd, limits)` | поставить роутер на `http.server` с пределами тела и формы |
| `url`, `full_url`, `signed_url`, `canonical` | адрес по имени маршрута |
| `signed()`, `verify(request)`, `etag()` | слой сверки подписи, сверка без слоя, слой метки версии страницы |
| `on_error(fn)`, `refusal(failure, request)` | свой обработчик отказов и ответ роутера на отказ |
| `json`, `text`, `html`, `redirect`, `no_content`, `stream` | помощники ответа |
| `view`, `fragment`, `view_stream` | страница, её кусок и страница потоком через движок `view`; общие данные страниц — настройкой `view_data` |
| `new(opts)`, `configure(opts)` | отдельный роутер и настройки общего |
| `routes()`, `status()` | объявленные маршруты и настройки роутера — без ключа подписи |

```lua
local router = require('tnt.router')

router.group('/api/v1', { middleware = { authenticated } }, function(r)
    r.post('/customers', create)
    r.delete('/customers/:id<uuid>', remove)
end)

router.serve('/build', 'public/build', { immutable = true })

router.get('/audit/export', function()
    return router.stream(next_piece, 200, { ['content-type'] = 'application/x-ndjson' })
end)
```

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov, рок http, зависимости пакета и соседи в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (569 проверок,
1621 мутант в двадцати пяти модулях). Почти всё
проверяется без сервера, через `dispatch`; стык с `http.server` —
тело, форма, поток, смена протокола, адреса — живым сервером на петле
и `http.client`. Часы, случайность и подключение соседей подменены
в проверках, файловая система — подменой `fio` под `tnt-fs`, записи
журнала ловит ловушка на `tnt-log`;
ограничения и слои, названные именем, проверяются против настоящих
`tnt-validate` и `tnt-middleware`, связка с обработчиком отказов —
против настоящего `tnt-error`.
